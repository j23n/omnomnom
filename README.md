# Omnomnom

An offline iOS nutrition tracker whose only job is to be a good entry mask for Apple Health. Type or speak one line, check what it resolved to, and the eight dietary nutrients go to Health as one food correlation. Searching a food and setting an amount by hand is still there behind it. No scores, no advice, no account.

`PLAN.md` is the technical plan, `docs/MILESTONES.md` the build status log.

## Layout

```
project.yml          the Xcode project, generated by XcodeGen; the .xcodeproj is not in git
Omnomnom/            app target (App, Model, FoodDB, Health, Features, Support, Resources)
OmnomnomShared/      app group store and widget snapshot, built into the app and the widget
OmnomnomWidget/      widget extension
Config/              the widget's Info.plist, which cannot live in a synchronised folder
OmnomnomTests/       Swift Testing bundle, with a small fixture database
Tools/fooddb/        Python pipeline that builds the bundled database
```

The folders are Xcode 16 synchronised folders, so `project.yml` describes targets and build
settings and never lists a source file: a new file needs no regeneration, only a new target
or a changed setting does.

## Git LFS

Images and screenshots are stored with Git LFS. Install it once per machine and clone:

```sh
brew install git-lfs
git lfs install
```

The app icon is the one exception: a small flat PNG kept in plain git so a checkout without LFS still builds. The same mark is in `docs/design/icon/mark.svg`, ready for Icon Composer.

## App icon

`Omnomnom/Assets.xcassets/AppIcon.appiconset/AppIcon.png` is rendered, not drawn. After changing the geometry in `Omnomnom/Support/Brand/BiteMark.swift` and mirroring it into the script, regenerate the PNG and commit it:

```sh
python3 Tools/icon/make_icon.py
```

Standard library only; `--size` and `--out` exist for previews.

## Build the food database first

The app loads `foods.sqlite` and `sources.json` from its bundle. Both live in `Omnomnom/Resources/`, are git-ignored, and are generated by the pipeline. Run it before the first Xcode build (see `Tools/fooddb/README.md` for details and options):

```sh
cd Tools/fooddb
python3 -m fooddb download                 # into Tools/fooddb/downloads/ (git-ignored)
python3 -m fooddb build --fdc downloads    # writes Omnomnom/Resources/foods.sqlite and sources.json
```

If the download host is unreachable, fetch the two FDC CSV zips by hand and point `build --fdc` at the folder holding the unzipped bundles:

```sh
python3 -m fooddb build --fdc ~/fdc --out ../../Omnomnom/Resources/foods.sqlite --sources-out ../../Omnomnom/Resources/sources.json
```

Without these files the app still launches, but search reports that the database is missing.

## Generate the project

The Xcode project is generated from `project.yml` and is not checked in. In the repository root, once per machine and whenever `project.yml` changes:

```sh
make bootstrap      # installs XcodeGen if it's missing, then generates the project
make project        # regenerates it when project.yml changed
```

## Build the app

Open the generated `Omnomnom.xcodeproj` in Xcode 27 and run the shared `Omnomnom` scheme on an iPhone or simulator running iOS 26 or later. The app runs on iOS 26 and is built against the iOS 27 SDK for the two calls that need iOS 27 (see `PLAN.md`): a photograph attached to an on-device prompt and the Health query for a time-limited authorization window. Xcode 26 builds it too, without those two, so it behaves as on iOS 26 there (`Omnomnom/Modules/Estimation/OnDeviceSDK.swift`). Signing is automatic; set your team in the target's Signing settings. The simulator's Health app accepts writes, so the whole flow can be tried there; only the device checks listed in `PLAN.md` need hardware.

From the command line, the same targets as the other j23n apps ([j23n/apple-ci](https://github.com/j23n/apple-ci)): `make test` (the pipeline's tests), `make build` (the app for the iOS Simulator, unsigned), `make test-app` (`OmnomnomTests` in the simulator), and `make ci-linux` and `make ci-macos`, which CI runs. CI builds and tests the app with Xcode 26, and with Xcode 27 once the hosted runners have it. `.apple-ci/apple.mk` holds the shared rules; `make update-apple-ci` refreshes it.

Swift 6 language mode, strict concurrency, default actor isolation `MainActor`. No third-party dependencies: XcodeGen writes the project file and is linked into nothing. The one package fetched at build time is j23n's own FeedbackKit, and only Debug builds use it (see Feedback).

## Feedback

Debug builds (the `FEEDBACK` compilation condition, set for the Debug configuration in `project.yml`) include in-app feedback with [FeedbackKit](https://github.com/j23n/feedbackkit): shaking the iPhone, taking a screenshot (a banner offers it) or Settings › Feedback opens a form with a screenshot of the screen, which Quick Look's Markup can annotate. The report goes to the owner's private inbox, [j23n/feedback](https://github.com/j23n/feedback), where it's triaged before an issue is filed here; the screenshot never leaves the inbox.

The screenshot carries nothing personal: FeedbackKit's `.allContent` redaction draws placeholders for every text and image in the app's views for the capture, and paints over the titles and text fields UIKit draws, so foods, meals, recipes, amounts, times, photographs and anything typed are hidden and only the layout and the tab bar's labels stay. It fails safe: a new view is hidden without being marked, and only a view marked `.unredacted()` would show, so don't mark one that shows someone's data. Charts keep their bars and lines without labels. Settings › Feedback turns it off, holds the GitHub token (a fine-grained token for j23n/feedback with Issues and Contents read and write, kept in the Keychain) and sends what's waiting. Release builds never create a feedback center (`Omnomnom/Support/FeedbackSupport.swift`).

## Modules

Barcode scanning is off until the user turns it on in Settings › Modules. Detection runs on the device through VisionKit; only the lookup goes out, as one request per new barcode to `https://world.openfoodfacts.org/api/v2/product/{barcode}.json`, sent with the User-Agent `Omnomnom/<version> (https://github.com/j23n/omnomnom)` that Open Food Facts asks clients to carry (the URL is the contact address). Results are cached in the local store for good, so a rescanned barcode never hits the network again; a miss, an offline lookup or an error opens the food editor with the barcode prefilled. No Open Food Facts data is bundled with the app, which keeps the ODbL share-alike clause out of scope; the Quantity sheet and the Sources screen carry the attribution the licence asks for. `Omnomnom/PrivacyInfo.xcprivacy` declares no tracking and no collected data.

## Tests

`OmnomnomTests` runs with Swift Testing against `OmnomnomTests/Fixtures/foods.sqlite`, built from the pipeline's synthetic fixtures. Regenerate it after a schema change:

```sh
cd Tools/fooddb
python3 -m fooddb build --fdc tests/fixtures/fdc --out ../../OmnomnomTests/Fixtures/foods.sqlite --sources-out ../../OmnomnomTests/Fixtures/sources.json
```

Pipeline tests: `cd Tools/fooddb && python3 -m unittest`.
